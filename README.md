# 通到微信（dsh-wechat-bridge）

> **这是修改版**：上游是 [Yuuyuko-uu/dsh-wechat-bridge](https://github.com/Yuuyuko-uu/dsh-wechat-bridge)（作者 Yuuyuko-uu，MIT）。本仓库（[xiao-peng-16/dsh-wechat-bridge-bot](https://github.com/xiao-peng-16/dsh-wechat-bridge-bot)）在原版基础上补了一批「实际用起来会疼」的地方，具体见文末「相对原版的改动」。

让 DSH 里的 AI 伙伴和微信双向聊天：**你在微信里发的话转进 DSH，伙伴说完一整轮，最后一句（和表情包图片）发回微信。**

**支持两种后端，不修改微信客户端文件。**
- `sqlite_uia`：收消息通过微信本地 SQLite 数据库（只读）；发送通过 Windows UI Automation 和剪贴板。
- `native_hook`：在已验证的微信版本上，通过 Native Hook 收发文本、图片和文件；Hook 回调可获得会话底层 wxid（群聊为 `xxx@chatroom`）。该模式依赖项目配置的 helper 和对应版本 profile，不是通用兼容模式。

Native Hook 当前仅对已验证的微信 `4.2.0.12` 开放图片接收 / 发送、文件发送和引用发送能力。引用回复需要微信服务器消息 ID；缺少有效 ID 时会退回普通文本。其他 profile 不会绕过指纹校验，媒体与引用能力保持关闭。

所以它用的是**你自己的微信号**，不是机器人。朋友收到的，就是你本人在说话。

## 它长什么样

```
sqlite_uia：微信本地库 ──> 插件里的 Python 桥接 ──POST /receive──> DSH 会话
          <──UIA 发送── 插件里的 Python 桥接 <──GET /outbox── DSH 会话
native_hook：微信原生 Hook ──> 插件里的 Python 桥接 ──> DSH 会话
             <──原生文本 / 图片 / 文件发送── 插件里的 Python 桥接 <──outbox── DSH 会话
```

宿主半边管会话绑定、权限、队列；Python 半边按所选后端负责收发、日记。中间走本机 HTTP。Native Hook 入站会把底层会话 ID 作为 `chatId` 传给宿主，宿主将它随本轮回复放进 outbox；发送时 Hook 优先使用这个 ID，旧 outbox 没有该字段才回退按显示名解析。

## 装

```
dsh plugin --profile desktop add github:thawline/dsh-wechat-bridge
```

或 设置 → 插件 → 安装，填 `github:thawline/dsh-wechat-bridge`。

装完**重启一次 DSH**，点击左侧插件栏里的 **🐋 通到微信**。

## 第一次用（三步）

1. **装依赖**：点「装依赖」。有现成的 Python 环境（装好 `wechatauto-replica` 的）就直接填「解释器」路径，不用建虚拟环境；没有就让它用系统 Python（3.10+）建一个。
2. **启动**：点「启动」，下面会滚日志，看到「桥接已就绪」就成了。
3. **选会话**：挑一间「默认会话」，打开「总开关」。先留着「试运行」看它记的「该发什么」对不对，再把试运行关掉。

之后在微信里跟**文件传输助手**说话，就等于跟伙伴说话；别人的私聊、群里的话也会转进来——但**外人只能聊天，动不了电脑**（见下面「权限」）。不想让某个人进来，填「入站白名单」（留空 = 谁都能进）。

## 不想装 Python？用自带的运行环境

本仓库的 Release 里有一份打好的 Python 3.12 运行环境（Windows x64，已经装好 `wechatauto-replica`、`uiautomation`、`numpy`、`Pillow`、`pywin32`、`comtypes` 等，不需要再联网装东西）。

```
解压 wechat-bridge-runtime-win64-py312.zip
把里面的 python 文件夹放到  ~/.dsh/wechat-bridge-runtime/python
（也就是 C:\Users\<你>\.dsh\wechat-bridge-runtime\python\python.exe 存在）
```

插件启动桥接时会自己找这个位置，不用填「解释器」、也不用点「装依赖」。想放别处也行，把那个 `python.exe` 的路径填进设置里的「解释器」就行。

> 这份环境是绿色版：整个文件夹搬到哪都能跑，删掉就等于卸载。装依赖时如果发现它是好的，会直接用，不会建 venv。

## 权限：只有主人能动电脑

| 谁 | 能干什么 |
| --- | --- |
| **主人**（`主人` 里填的 wxid / 昵称） | 什么都能 —— 聊天、读文件、跑命令、改设置 |
| **别人** | 聊天 + 设置里「外人可用工具」列出的那几个（默认 `web_search` / `web_fetch` / `send_meme`）；其余工具硬拦（不是靠嘴劝，是在工具执行前直接拒掉） |

实现方式：外部消息进来时，插件给那间会话的 agent 挂一道 `tools.guard`。这一轮如果是外人叫醒的，除白名单里那三个工具外，别的调用一律拒绝。这一轮结束闸就抬起来。

所以外人就算在微信里说「帮我删掉 D 盘」，工具层直接拒绝，模型只能回一句「这个我做不了」；但说「出个大冒险」「找个表情包」是能办的。

⚠️ 前提是宿主要提供 `tools.guard`（本版本 DSH 有）。没有的话日志会警告一句「这层宿主没有 tools.guard」，那就只剩嘴上约束了。

> 另外：微信轮是后台跑的，界面上没人点「允许」。DSH 发现没有审批 answerer 时，会把需要审批的工具整批从工具表里移除——所以插件自己挂了一个 `approval/request` 监听，把只读 / 联网那几样（`外人可用工具` 里的）直接放行。跑命令、读写文件、改设置不在名单里，照旧需要审批。

## 谁能进来（入站白名单）

默认**谁都能发进来**：任何能给这个微信号发消息的联系人，都能让本机模型跑一轮——动不了电脑（上面那道闸），但会花你的额度。

想在「谁能触发」这一层就收口，去设置里填**入站白名单**：填了之后只有名单里的 wxid / 昵称能发进来，其他人连一轮都不会起，日志里记一句就丢掉。**主人永远放行，不用写进来**。留空 = 恢复成谁都能进。

两层的关系：

| 层 | 挡什么 | 怎么配 |
| --- | --- | --- |
| 入站白名单 | 谁的消息能触发一轮（花额度） | 留空 = 谁都能进；填了只放行名单 |
| 外人只能聊天 | 触发之后能不能动电脑 | 默认开；别人只放行联网和表情包 |

## 群聊

| 设置 | 作用 |
| --- | --- |
| **群上下文条数** | 被叫到时，往前读几条群聊天一起给模型看。默认 6，填 0 = 不带 |
| **群回复间隔秒** | 同一个群，两条回复之间至少隔几秒。默认 30，填 0 = 不限 |
| **群聊日记** | 群里**所有**消息（不点名的也记）按天写成 markdown |
| **不回谁（屏蔽）** | 一条一个标签，命中的会话 / 人不回复也不记日记（默认：微信运动、微信团队、微信支付、服务通知、订阅号消息、折叠的群聊） |

群里默认**只有被点名才进来**：正文里出现「点名别名」之一才算在叫它，默认是 大肥鱼 / 肥鱼 / 小肥鱼 / 小客服。别名在设置里改，改完 30 秒内生效，不用重启桥接；填空 = 用桥接内置的默认。

被叫到之外还有一层**追话**：本鱼在群里说完话，后面 N 句内（默认 3，设置里调）进来的消息会交给记忆模型判断「是不是在接本鱼的话」——明确 yes 才回，看不出就不回，不乱插嘴。追话不吃群频率闸：人家是紧接着回你的，不该被 30 秒冷却挡掉。

再往下是**话题规则**：一条一条的「词 + 怎么回」，命中哪个词就把那条写法塞给模型，比统一一句「想接就接」有分寸。比如：

```text
白饭    →  哭穷要饭，说本鱼快饿死了
token   →  嘴硬说那是必要的推理过程，两秒后心虚认错
下雪    →  （「怎么回」留空 = 只允许插一句，不强制）
```

「怎么回」留空就只是允许插话、不强制回；照样吃群频率闸，免得一提到就刷屏。适合挂「白饭」「token」这种它自己会接的梗，别挂「在」「好」这种满屏都是的词。老版本单独那一栏「话题唤醒」会自动并进来，变成没有「怎么回」的条目。

每条规则后面还能配限流：`[60] 秒内最多 [3] 次`——只算这个词自己的窗口，0 = 沿用全局「群回复间隔秒」。所以「欢迎新人」可以设 60 秒内最多接 2 次，「嘟嘟嘟」可以完全不限。

日记存在 `~/.dsh/wechat-diary/<YYYY-MM-DD>/<群名>.md`，一天一个文件，当天追加：

```markdown
# 组队叫战狗 单排叫野狗 · 2026-10-26

- 15:07 饮茶：现在有比赛？
- 15:08 Zierk：昨晚一点
```

## 总结聊天记录

群里发「总结一下今天的瓜」「昨天下午聊了啥」「这周群里都干了啥」，桥接会**直接从微信消息库按时间取**那一段，连同写法指令一起交给模型——不依赖日记 md（日记只记桥接跑起来之后的消息）。

两个让总结不写成流水账的处理：

- **同人连发合并**：同一个人 90 秒内发的几条并成一行（`A / B / C`），不然「我沉迷盲盒」「那段时间」会被拆成三行，读起来像三个人抢话。
- **写法指令**：默认要求分成几件事、每件起小标题、抄最有梗的原话、分清玩笑和事实、别逐条转述。设置里「总结提示词」留空就用内置那套，想换口味可以整段覆盖。

总结规则还有一份完整版，放在 `.dsh/skills/wechat-group-digest/SKILL.md`，DSH 里可以用 `/wechat-group-digest` 直接加载。

时间窗按问句里的说法猜，能认到具体时刻：

- 区间：「今天下午 3 点到 5 点」「昨天 21:30-23:00」「早上 9 点半到 12 点」「下午三点到五点」
- 单点：「晚上 8 点」按一小时算
- 相对：「最近两小时」「最近 30 分钟」「刚才」
- 日期 + 时段：「今天 / 昨天 / 前天 / 本周 / 上周 / 这几天」+「凌晨 / 早上 / 上午 / 中午 / 下午 / 傍晚 / 晚上」

取数上限 400 条、总字 12000，超了会标注「另外 N 段没放进来」。

## 记忆

桥接在本地记一份「谁是谁」的账，明文 SQLite：`~/.dsh/wechat-memory/memory.db`。

- **成员画像 / 群像**：启动 10 分钟后、之后每 6 小时，扫一遍当天日记，让模型写「成员一句话画像 + 群氛围 / 兴趣 / 梗」。每条画像都要附一句**原文证据**，对不上就当编的丢掉。
- **好感账本**：点名、引用、接话、被夸、被骂各按固定分值记一笔（分值表写死，模型插不上手，还能一条条翻账）。
- **记忆注入**：这个人在跟本鱼互动时，把「对他的印象 + 好感 + 群像」拼一小段（300 字内）塞进上下文。
- **认领判断**：追话、引用消息这类「像在跟本鱼说话」的场景，由记忆模型判断到底在跟谁说话。

记忆要花模型的钱：设置里填「记忆密钥」（留空就用 DSH 自己的密钥），「记忆模型」默认 `deepseek-flash`。没配密钥时不烧钱——好感账本照常记，画像合成和认领判断跳过。

## 表情包

伙伴在回复里写 `[表情: 描述]`，插件会去 `dsh-meme` 的表情库里按 caption / 关键词找那张图，**当图片消息发到微信**，那串描述本身不会出现在正文里。

找不到对应图片时保持原样（发出去的就是文字），不会丢内容。

## 「文件传输助手」

自己发给自己的消息本来会被跳过（防自问自答），但文件传输助手放行 —— 那是你留给自己的对话窗。两道防回环：

1. 自己刚发出去的几条，按文本比对跳过（比对前先规整空格换行）
2. 往外发完的 12 秒内，文件传输助手里冒出来的消息一律不读

## 也可以直接说

不想点设置页的话，跟伙伴说一句就行 —— 插件挂了四个工具：

| 工具 | 参数 | 干什么 |
| --- | --- | --- |
| `wechat_block` | `{who, action: add / remove / list}` | 加/删/看「不回谁」名单 |
| `wechat_bind` | `{chat, session, action}` | 把某个微信聊天接到某间会话；`session` 可以只报标题（如「主要聊天记忆」），它自己去找那一间 |
| `wechat_send_file` | `{路径, 聊天?, 文本?}` | 把本机文件当文件消息发到微信（主人那一轮才放行） |
| `wechat_member_update` | `{动作, ...}` | 查询或修改 `~/.dsh/wechat-memory/memory.db` 中的结构化成员资料；`动作=查` 按性别 / 地区 / 有对象 / 年份 / 关键词筛选，所有人可查；`动作=改` 仅主人可用 |

例：「以后别理「拼多多」」「把「组队叫战狗」这个群接到主要聊天记忆那间」「查一下福建的男生」「把 momo 的地区改成山东」。

## HTTP 接口

| 方法 | 路径 | 干什么 |
| --- | --- | --- |
| POST | `/dsh-wechat-bridge/receive` | 收：`{text, 图片?, 图片类型?, chat, chatId, chatType, sender, senderId, nativeMessageId?}` → 转进会话；`chatId` 是好友 wxid 或群 ID |
| GET | `/dsh-wechat-bridge/outbox` | 发：取走待发队列；队列包含显示名 `chat`，以及有来源时的底层会话 ID `chatId` |
| POST | `/dsh-wechat-bridge/outbox/ack` | 发完回报 |
| GET | `/dsh-wechat-bridge/state` | 状态、配置、会话、日志 |
| POST | `/dsh-wechat-bridge/save` | 存配置 |
| POST | `/dsh-wechat-bridge/send` | 手动发：`{chat, chatId?, text?, 图片?, 文件?}`；`chatId` 可指定好友 wxid / 群 ID；`文件` 是本地路径数组 |
| POST | `/dsh-wechat-bridge/test-send` | 真发一条测试句 |
| POST | `/dsh-wechat-bridge/vision-test` | 试看一张本地图片：`{图片, 类型?}` |
| POST | `/dsh-wechat-bridge/bridge/install` | 装依赖 |
| POST | `/dsh-wechat-bridge/bridge/start` / `stop` | 起停桥接 |

## 边界与风险

- **图片和表情包会先“看”一眼**：收到图片 / 表情包时，桥接先把文件落盘，宿主用视觉模型写成一句中文描述再转进会话；没配视觉密钥时会标「没看清」，不会挡消息。`sqlite_uia` 使用本地库媒体能力；Native Hook 仅在已验证 profile 上使用原生图片接收回调。语音、视频仍然跳过。
- **发送会抢微信窗口焦点**。正常情况不抢前台，只有发送失败重试时才把微信拉到前面。
- **同一个微信号别同时开两个桥**（比如鲸鲸的桥接），会抢窗口、发送会乱。
- 微信个人号自动化不是官方接口，**有封号风险**，建议先用小号 / 测试号。
- **后端与兼容范围**：`sqlite_uia` 发送依赖 Windows UI Automation；Native Hook 的媒体 / 引用调用按精确 DLL 指纹和 profile 放行，目前只对已验证的微信 `4.2.0.12` 开放对应能力。微信升级后不要绕过校验，需先验证新版本 profile。
- **引用回复限制**：Native Hook 引用需要原消息的微信服务器消息 ID。拿不到该 ID 时会安全退回普通文本，不会拿发送者 wxid、显示文字或本地数据库 ID 冒充。

## 相对原版的改动

原版能跑通，但真天天用就会疼。这一版补的都是那种「用着用着才炸」的地方：

- **同会话发消息不再抢前台**：微信最小化着也能发，不把窗口拉出来、不动鼠标。切会话（私聊↔群）时窗口会短暂露一下，发完自动收回。
- **输入框防残留**：以前发送失败时字会留在输入框里，下一条回车就把它带出去，同一条消息发两遍。现在发送前先清空，失败时也不再靠真实鼠标点「发送」按钮（那会让鼠标满屏乱飞）。
- **Native Hook 收发适配**：支持已验证的微信 `4.2.0.12` 原生文本、普通图片接收 / 发送、文件发送；能力按 profile 精确开放，其他版本不绕过 DLL 指纹校验。
- **Hook outbox 使用底层会话 ID**：入站时把好友 wxid / 群 ID 作为 `chatId` 送入宿主，宿主在本轮 outbox 带回 `chatId`；Hook 发送优先使用它，兼容旧队列时才按显示名解析。
- **Native Hook 引用回复**：仅当拿到有效微信服务器消息 ID 时发送原生引用；ID 缺失或引用失败会退回普通文本，不伪造引用。
- **发图以数据库为准**（`sqlite_uia`）：以前接口说成功、其实没发出去（或者反过来）。现在发完去微信库里查有没有新图片，查到才算成功，避免重复发。
- **群聊查名修正**：群的昵称查不到时用 `group_name_to_id` 兜底，否则群消息永远查不到（会导致重复发送判断失效）。
- **一轮里多条回复会拼起来发**：以前同一轮的第二句会覆盖第一句，微信只能收到最后一句。
- **总结不再写流水账**：同一个人 90 秒内的连发合并成一行，注入的写法指令默认要求分组、抄原话、分清玩笑和事实；设置里的「总结提示词」留空就用这套默认，可整段覆盖。
- **桥接会自己回来**：插件加载时若总开关开着，自动启动桥接（DSH 重启不用再手动点）；进程意外退出 15 秒后自动拉起，最多连拉 5 次，手动点「停止」不会被拉回。外加一道看门狗：每 30 秒检查一次，桥接不在就拉起；在但 90 秒没心跳（桥接每 30 秒报一次）就当假死，杀掉重来。
- **临时目录兜底**：某些嵌入式 Python 探测不到可写的 `TEMP`（安全软件拦着时会这样），桥会退到自己的 `tmp/` 目录，不然连微信数据库都打不开。

## 开发自测

改了 `lib/host.js` 或 `lib/client.js` 之后，两个脚本可以直接跑（不用开 DSH，也不碰真实配置 —— 记得把 `DSH_HOME` 指到临时目录）：

```powershell
$env:DSH_HOME="$PWD\.testhome"; node _selftest.mjs         # 假 ctx 跑一遍宿主：保存 / 绑定 / 屏蔽 / 两个工具
$env:DSH_HOME="$PWD\.testhome"; node _selftest_client.mjs  # 假 React 把设置页渲染一遍：加标签、点绑定、轮询不冲掉
python _selftest_summary.py                                # 抽「历史转文字」真源码：连发合并、90 秒边界、截断
```
